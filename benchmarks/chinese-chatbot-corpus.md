## 1. 结论先行

| 指标 | 结果 |
| --- | ---: |
| **严格召回率 @3**（所有要点都进前 3） | **53/68 = 77.9%** |
| **宽松召回率 @3**（前两个要点至少命中一个） | 54/68 = 79.4% |
| 严格召回率 @1 | 48/68 = 70.6% |
| 严格召回率 @6 | 54/68 = 79.4% |
| MRR（首个要点首次命中排名） | **0.948** |
| 负样本零召回 | **5/6** |
| 抽取覆盖：所有要点在 fact 里存在 | 57/68 = 83.8% |
| 抽取覆盖：至少一个要点在 fact 里存在 | 59/68 = 86.8% |
| 查询延迟（预热第二遍） avg / p50 / p95 | **0.306 / 0.264 / 0.481 s** |
| top-3 平均字符数 | 43 |
| 抽取出的事实 / 父实体 | 74 条 / 39 个 |
| 图谱规模 | 公开投影 285 节点、394 边（另有 74 条 fact 不在投影里） |
| 批次封存-抽取 | 10/10 `published`，总抽取耗时 713.7 s |
| 原生 MemOS 2.0 对照 | 严格@3 82.4%，查询延迟 0.585 s，MRR 0.908 |

**一句话结论**：在“事实型问答 + 闲聊/字幕噪声”的语料上，项目先按批次封存、再抽取、再查询，
**严格召回率 77.9%、MRR 0.948、平均 0.285 s**；32 个探针里有 **24 个两种问法都过**，
**26 个至少过一种**。同语料原生 MemOS 2.0 的严格@3 是 **82.4%**（+4.4 pp），
但查询延迟 **0.585 s**（本项目的 1.9×）、top-3 **125 字**（2.9×）、MRR **0.908**（低于本项目的 0.948）。
主要失分不在向量召回，而在**抽取阶段没有为“定义型/抽象概念/裸人名”的回合生成 fact**；
另有少量排序漂移和一个负样本误召回。

> 口径：本工程 `built-in/memos` 插件的自动召回和 `memos_search_memory` 工具最终都调用同一个
> `/graphiti/search`；插件层只做格式化、来源标注和注入边界，不改变候选与排序。所以这里的数字
> 就是“记忆系统 + memos 召回”共用的底座能力。**原生 MemOS 2.0 的对照见第 8 节**；
> 更早的 alias/bluefish 历史数字见第 9 节。

## 2. 这组语料是怎么落地的

### 2.1 上游仓库只给脚本，不给数据

`codemayq/chinese-chatbot-corpus` 仓库本身只有清洗脚本（`process_pipelines/*.py`），
8 个语料包放在阿里云盘 / Google Drive。本机访问 Google Drive 时连接被重置，阿里云盘没有
客户端，因此按该仓库 README 列出的**上游源**取数，并沿用它的清洗语义：

| 源 | 上游 | 本次用途 | 是否使用 |
| --- | --- | --- | --- |
| chatterbot | `gunthercox/chatterbot-corpus` | 32 个探针 + 60 个中性填充回合 | ✅ |
| subtitle | `candlewill/Dialog_Corpus` 里的 `dgk_shooter_min.conv` | 2 批字幕对话噪声（20 回合） | ✅ |
| xiaohuangji | `candlewill/Dialog_Corpus` | 已下载并抽样，公开语料含明显成人内容，未进入交付集 | ❌ |
| ptt / douban / qingyun / tieba / weibo | 各自上游或网盘 | PTT 下载被重置；douban 只取到 test 集且是分词文本；青云/贴吧/微博无公开直链 | ❌ |

> 结论里不把“只用了 2 个源”藏起来：这是一组**可复核的事实型语料 + 两类噪声**，
> 不是全量 8 源的代表性抽样。限制一节会再说明。

### 2.2 探针怎么选

从 chatterbot 的 `history / trivia / literature / science / ai / politics / sports / money`
里选 **32 个“问题 + 具体答案”对**，例如：

- `谁发明了电灯泡` → `托马斯·爱迪生。`
- `第一颗人造地球卫星的名称是什么?` → `斯普特尼克1号`
- `是谁写的科学怪人` → `玛丽·雪莱。`
- `有多远是太阳` → `太阳是离地球约93万英里。`

每个探针写 **2 条测试问法**，原问题不作为查询：

1. 同义/换序的直问（如“电灯泡是谁发明的？”）；
2. 更间接的问法（如“之前聊到的那位发明灯泡的人叫什么名字？”）。

另有 4 条**跨探针多跳**查询和 6 条**负样本**，共 **74 条查询**。

### 2.3 批次结构

| 批次 | 类型 | 回合 | 内容 |
| --- | --- | ---: | --- |
| cb-b01 ~ cb-b06 | 探针 | 12 × 6 | 每批 5–6 个探针，穿插 6–7 个中性 chatterbot 回合 |
| cb-b07 ~ cb-b08 | 噪声 | 10 × 2 | chatterbot 的中性寒暄/情绪/玩笑回合 |
| cb-b09 ~ cb-b10 | 噪声 | 10 × 2 | subtitle 电影对白，按 2 回合一组配对 |

总计 **112 个回合**。探针不是连续堆在一起，而是隔一个填充回合出现一次，避免“整段话一起被召回”。

## 3. 批次封存 → 抽取

每个回合都走：

```text
POST /graphiti/sessions/turn      （user_content + assistant_content + complete=true）
POST /graphiti/sessions/close    （explicit_end）
POST /graphiti/ui/warm-layer/seal       ← 只封存批次，不抽取
POST /graphiti/ui/warm-layer/checkpoint ← 封存后再送抽取
轮询 /graphiti/ui/warm-layer/{role} 直到 published
```

关键点：**seal 和 checkpoint 是两次独立调用**，不是“关闭会话就自动抽取”。封存后正文仍留在温层，
checkpoint 冻结批次并走与 TTL 相同的发布路径；发布成功后温层正文被清掉（日志里的
`warm_batch_evicted: queued_extraction_published`）。

## 4. 查询与判定

- 接口：`POST /graphiti/search`，`top_k=6`，`user_id=feiniu_default`。
- 当前配置：`graphiti-recall-v6`，`semantic_threshold=0.25`，
  `direct_rerank_threshold=0.45`，`relative_floor_ratio=0.4`，`rerank_enabled=false`。
  因此本次的 `rerank_score` 等同语义分，**没有开 qwen3 精排**。
  Embedding 为 DashScope `text-embedding-v4`（1024 维），抽取/对话模型为 DeepSeek `deepseek-v4-flash`。
- 判定取**前 3 条**；只统计长期记忆（fact / node / relation），排除温层与聊天记录。
  实测温层在全部批次发布后已清空，**全通道结果与长期记忆结果完全一致**；74 条查询的 top-3
  共 158 条命中，**全部是 fact**。所以这组数字不是“最近几轮还在上下文里”抬出来的。
- 匹配前去掉 `[f_…]` 事实 ID 和“（经关系…）”注释，避免 UUID 里的数字造成假阳性。
- 每个要点是一组同义词，命中任一即算该组命中；严格 = 所有组都命中，宽松 = 前两组至少一组命中。
- 失败分类里的 `extraction_miss` 指**期望要点不在任何 fact 里**，不等于该查询零召回；
  p15-q2 这类会召回相关作品 fact，但缺的正是“作者”这个要点。
- 另外按 `built-in/memos` 插件的自动召回参数（`top_k=3`）重跑全部 74 条：严格率仍是
  **77.9%**、负样本仍是 **5/6**，74 条中只有 3 条的第 3 位候选不同（p13-q1、p13-q2、p21-q2，
  都不改变判定）。说明插件层与本次查询口径一致。

## 6. 失败分析

### 6.1 定义型 / 抽象概念没有生成 fact（8 条查询，4 个探针）

| 探针 | 源答案 | 抽取结果 |
| --- | --- | --- |
| p26 金手套 | `金手套。` | 无 fact；查询零召回 |
| p30 历史 | `历史：政治,经济,军事事件…` | 无 fact；查询零召回 |
| p31 陀螺 | `陀螺.` | 无 fact；查询零召回 |
| p32 经济学 | `资源稀缺的条件下,分配的研究。` | 无 fact；查询零召回 |

这 4 个探针贡献了 **8/15 条失败查询**。它们的共同点不是“没有实体”，而是答案落在
**类别/定义/抽象概念**上：

- 金手套、陀螺是“一个词的名词答案”；
- 历史、经济学是“学科/类别”本身，不是某个具体对象。

抽取器当前的事实通道要求先有可命名的实体，再把陈述挂上去；这类回合要么没有实体，
要么实体太泛，最后一条 fact 也不产出。**这是本轮最大的能力缺口**，比排序问题更值得先修。

### 6.2 裸人名回合的“人名 → 作品”关联丢失（4 条查询，2 个探针）

源对话是：

```text
用户：弗兰克·赫伯特
助手：我认为,沙丘是一个极好的故事。你看电影？

用户：阿西莫夫
助手：我喜欢的基础三部曲。
```

抽取出的是：

```text
《沙丘》是一个极好的故事。
语料召回测试员喜欢基础三部曲。
```

也就是说，系统把“作品”抽出来了，但**没有把用户说的裸人名绑定到作品上**。问
“《沙丘》是谁写的”“基础三部曲是谁写的”时，fact 里没有“赫伯特/阿西莫夫”，于是失败。

需要说明的是：**语料并没有明说“赫伯特写了沙丘”**，只说了人名和作品在同一回合出现。
这两条题面依赖会话共指，属于基准题面偏强；系统的实际缺陷是“没有建立会话级关联”，
而不是“把作者记错了”。p15、p17 应归入“关联抽取缺失”，不宜简单归为事实错误。

### 6.3 排序漂移（2 条查询）

| 查询 | 现象 |
| --- | --- |
| p23-q1 “你是什么类型的计算机？” | 前 3 全是“软件可以在 Windows / Mac OS 运行”，没有把 `任何支持 Python 的计算机` 排进来；换成 q2（“依赖什么语言…”）就能命中 |
| p24-q1 “你和人类有什么不同？” | 正确 fact `语料召回测试员没有感情，缺乏所有情感、梦想、愿望、创造力…` 存在，但前 3 被字幕噪声 `主人解开了Dakara武器之谜` 占据；换成 q2（“缺乏哪些特质”）就命中 |

p24 尤其说明一个问题：**抽象的自指问题（“你…什么不同”）缺少实体锚点，容易被近期高显著性的
叙事 fact 抢走**。这不是抽取失败，而是排序/查询改写问题。

### 6.4 多跳（1 条）

- **m04** “《哈比人》和《沙丘》的作者分别是谁？”：哈比人 → 托尔金命中，沙丘 → 赫伯特缺失
  （同 6.2），所以只拿到一半。
- m01、m02、m03 都通过：前 3 能同时容纳两条事实。

### 6.5 负样本（1 条）

| 查询 | 返回 | 判定 |
| --- | ---: | --- |
| n01 《三体》的作者是谁？ | 6 条 | 误召回：返回了 `JRR托尔金是《哈比人》的作者`、`《葡萄园》是托马斯·品钦写的` 等“书—作者”家族 fact |
| n02 珠穆朗玛峰有多高？ | 0 | pass |
| n03 长城有多长？ | 0 | pass |
| n04 特斯拉的创始人是谁？ | 0 | pass |
| n05 光合作用的产物是什么？ | 0 | pass |
| n06 法国大革命是哪一年开始的？ | 0 | pass |

n01 不是“命中了三体”，而是**语义邻居**：查询和“某本书的作者”结构相同，检索把同类 fact
都拉进来了。对陪伴型记忆来说，这类结果如果原样注入，模型容易把“托尔金”错接到《三体》上。
零召回口径对语义检索偏严，但这个误召回确实存在。

### 8.4 逐条胜负

68 条正样本中：

没有出现“原生全胜/项目全胜”的类别，差距集中在具体回合的抽取形态上。

### 8.5 原生为什么在 p23/p24/p31/p32 赢

原生 `fine` 写入会把一个回合压成一条**带答案的摘要**，例如：

```text
2026年11月4日06:55，助手在回答用户关于“你和人类有什么不同”的问题时称，
AI 缺乏所有情感、梦想、愿望、创造力、野心，尤其是主观性。
```

这条摘要同时包含问题词和答案，所以 p24-q1 直接命中；p23-q1 的“任何支持 Python 的计算机”、
p31 的“陀螺”、p32 的“资源稀缺/分配”也都以同样方式保留下来。本项目在这四个点上分别是
“排序漂移”和“抽取缺失”，原生用摘要绕开了这两个问题。

### 8.6 本项目为什么在 p16/p28 赢

原生的摘要并不总是保留答案。它有时只记录“用户问了什么”，把答案丢掉：

```text
p16：用户在与助手的对话中提及“儒勒·凡尔纳”。用户未进一步说明具体意图、相关作品……
p28：用户向助手询问是否了解美国内战。对话中用户未进一步说明自己对该话题的具体看法……
```

本项目的 fact 则保留了 `儒勒·凡尔纳与《月球旅行记》相关`、`对各州之间的战争感兴趣`，
所以两条问法都命中。原生的摘要质量在同一份语料上并不稳定：有时保留答案（p31/p32），
有时只剩“用户提问”这一层（p16/p28/p30）。

### 8.7 延迟与上下文的账

把查询延迟单独拉出来看：

| 查询类型 | 本项目 avg / p95 | 原生 avg / p95 |
| --- | ---: | ---: |
| 探针（64 条） | **0.309 / 0.43 s** | 0.568 / 0.741 s |
| 多跳（4 条） | **0.316 / 0.281 s** | 0.646 / 0.514 s |
| 负样本（6 条） | **0.271 / 0.300 s** | 0.723 / 0.757 s |

预热后原生 avg 0.585 s、p50 0.548 s，分别是本项目的 **1.9× / 2.1×**；p95 0.841 s，是 1.7×。
按“1 秒内返回”这条在线聊天硬指标，本项目 **73/74**，原生 **71/74**；两边都会偶发 1 s 级抖动，
不是某一方独有。top-3 上下文 125 字 vs 43 字，意味着同样 8000 token 预算下，本项目能放更多条
不同事实，原生更容易把预算花在一条长摘要上。

离线写入侧，原生 112 次 add 共 963.2 s（avg 8.6 s、p95 14.1 s）；本项目 10 个批次
共 713.7 s（avg 71.4 s/批，折合 6.4 s/回合）。原生逐回合摘要更贵，本项目批量抽取更省。

### 8.8 一个必须说清的评分偏差

原生 m04 被判为“通过”，但看 top-3 内容：

```text
1. 《哈比人》由 J.R.R.托尔金所写。
2. 《沙丘》是一个极好的故事。
3. 用户在与助手的对话中提及了“弗兰克·赫伯特”。
```

第 3 条只说“提及赫伯特”，**没有说赫伯特写了《沙丘》**；关键词判定因为 `赫伯特` 出现在
top-3 就放过。这是原生摘要式记忆 + 关键词判定的**词面膨胀**，不是真正的多跳回答。
反过来，本项目在 p15/p17 也确实没有建立“人名 → 作品”的关联。两边各有各的关联缺失，
不能把原生这 1 条算成完整胜利。

如果扣掉 m04 这条词面通过，原生是 55/67 = 82.1%，本项目 53/67 = 79.1%，差距约 3.0 pp。

### 8.9 结论

- **要 top-3 覆盖、能接受约 1.9× 延迟和 2.9× 上下文**：原生 MemOS 的摘要式记忆在 top-3 覆盖上更高，
  尤其在定义型问答和抽象自指问题上。
- **要首条命中、低延迟、紧凑上下文、离线省时**：本项目更合适；MRR 0.948 vs 0.908，
  p95 0.48 s vs 0.84 s，top-3 43 字 vs 125 字。
- **两边共同的短板**：定义型问题的答案保留不稳定；负样本的“同类家族”误召回都存在；
  裸人名 → 作品/属性的会话关联都会丢。
- 对本项目最划算的改进不是照搬原生摘要，而是**在抽取阶段补“定义型事实”和“回合级关联绑定”**
  （见第 10 节），这样可以用更低的延迟拿到原生在 p23/p24/p31/p32 上的收益。

### 8.10 写入阶段的 LLM 调用与 token

两边的写入都不是“只存文本”，但调用粒度不同。

**原生 MemOS 2.0**：`/product/add` 的 `mode=fine` 会走 `SimpleStructMemReader`，每个 1024-token 窗口调用一次 LLM（提示词约 2.8k 字符，含示例），返回 `memory list` 和每回合 `summary`；`text_mem.add` 只做向量化和写库。本次 `async_mode=sync`、`MOS_ENABLE_SCHEDULER=false`、`ENABLE_PREFERENCE_MEMORY=false`，所以是 **112 回合 = 112 次抽取调用**。若改成 `mode=fast` 则不调用 LLM，只做分块，但记忆形态不同，本次未采用。

**本项目**：`/sessions/turn` 不调用 LLM，`seal` 也不抽取；只有 `checkpoint` 对每个批次跑完整抽取：Graphiti 实体/关系抽取与去重解析、实体陈述、联想 hook，随后是“写日记 → 从日记抽记忆”两遍。10 批共 91 次调用，平均 9.1 次/批。

| 阶段 | 调用 | 输入 token | 输出 token | 合计 |
| --- | ---: | ---: | ---: | ---: |
| 原生 MemOS（fine，112 回合） | 112 | 160,289 | 120,274 | 280,563 |
| 本项目知识抽取（10 批） | 71 | 168,174 | 59,027 | 227,201 |
| 本项目日记 + 记忆（10 批） | 20 | 7,882 | 12,739 | 20,621 |
| **本项目合计** | **91** | **176,056** | **71,766** | **247,822** |

| 每回合指标 | 本项目 | 原生 MemOS | 差异 |
| --- | ---: | ---: | ---: |
| LLM 调用次数 | 0.81 | 1.00 | 原生 +23% |
| 输入 token | 1,572 | 1,431 | 本项目 +9.8% |
| 输出 token | 641 | 1,074 | 原生 +67.6% |
| 合计 token | 2,213 | 2,505 | 原生 +13.2% |

- 原生输入略少，因为每回合只带固定模板 + 单回合对话；本项目每批 prompt 要带抽取规则、上一批 episode、已有实体/关系，单次输入约 2.4k，但调用次数少。
- 原生输出高，因为**每回合都要求 120–200 字 summary**；本项目每批只写一篇日记，记忆节点也只从日记抽，摘要开销从 112 次降到 10 次。输出 token 单价通常高于输入，按金额算差距会比 13% 更明显。
- 两边都不含 embedding：原生对每条记忆、本项目对实体/fact 还会调用 `text-embedding-v4`，这部分按 embedding 用量另计。
- 方法：同模型 `deepseek-v4-flash`；在相同 prompt/图上重放抽取，usage 取 DeepSeek 返回的 `prompt_tokens` / `completion_tokens`；日记和记忆两遍用实际存档日记重放。温度采样和图状态差异带来几个百分点误差；本项目 91 次调用是重放值，历史实际运行因去重/重试会略有不同。

## 9. 和既有基准的关系

仓库里已有两组召回实测：

- [别名/代号召回对比](../alias-recall-test/README.md)：本项目严格 41.7%，原生 MemOS 54.2%；
- [蓝鱼联想召回](../memos2-benchmark/README.md)：本项目严格 68.4%，原生 MemOS 逐轮 63.2%。

这两组是**对抗性联想/多跳**任务，本次是**事实型问答 + 噪声**，难度和判定都不同，
**77.9% 不能直接和 41.7% / 68.4% 横向比较**；本次同语料的原生对照见第 8 节，
下面两组更早的任务只作为“同项目不同任务”的背景。能说的是：

- 在“抽取出干净事实、查询直接指向该事实”的场景，本项目很强（MRR 0.948，top-3 只有 43 字）；
- 一旦问题需要**定义/抽象概念/会话共指**，抽取阶段就会先丢信息，后面再好的排序也救不回来。

## 10. 建议的修复优先级

1. **补“定义型事实”通道**：当回合是“X 是什么/谁”且答案是一个名词或类别时，生成
   `X 是 Y` / `X 属于 Y` 的 fact，不要求先有具体实体。p26/p30/p31/p32 直接受益。
2. **回合级关联绑定**：用户只说了裸人名、助手回答了作品/属性时，生成
   `人名 -[提及/作品]-> 作品` 的关联 fact。p15/p17、m04 直接受益。
3. **抽象自指查询的处理**：对“你是什么/你和人类有什么不同”这类无实体锚点的查询，
   优先召回挂在 AI 角色节点上的 fact，降低高显著性叙事 fact 的权重。p23/p24 受益。
4. **负样本的“同类家族”抑制**：对“书—作者”这种结构相同、实体不同的查询，
   加实体支撑或相对地板；当前 n01 会把整个家族拉进来。
5. 评估是否开启 `rerank`：本次 `rerank_enabled=false`，p23/p24 的排序漂移可能部分由精排缺失造成；
   但开精排会抬高延迟，需要单独做 A/B。

## 11. 限制

- **语料覆盖有限**：只用了 chatterbot 与 subtitle 两个上游源；仓库网盘版 8 源未全量落地。
  xiaohuangji 因公开语料含成人内容被排除；PTT 下载被重置，douban 只取到分词 test 集，
  青云/贴吧/微博没有公开直链。
- **规模小、单次运行**：32 个探针、74 条查询，一次运行；没有多 seed、没有置信区间。
- **判定是关键词组匹配**，不是 LLM/人工裁判；严格口径偏保守，换一种说法但答对会被记为失败。
- **chatterbot 是机器翻译的英文对话**，中文表达不自然；它不是本工程真实用户聊天的分布。
- **题面含共指假设**：p15/p17 依赖“人名 + 作品同回合出现 = 作者关系”的推断，语料没有明说。
- **角色是新角色**：没有历史记忆干扰，也没有多角色串扰；结果不代表长期使用后的图谱质量。
- **当前配置未开精排**：`rerank_enabled=false`，排序能力没有被完整评估。
- **原生对照的判定偏差**：原生返回的是摘要，摘要常复述问题，关键词判定可能高估；m04 就是
  “提及赫伯特”被当成“赫伯特写了沙丘”的例子。扣掉这条后原生 82.1% vs 本项目 79.1%。
- **原生搜索是 fast 模式 + cosine_local**，本项目未开 rerank；两边排序器不同。
- **原生写入是逐回合 LLM 摘要**，存在摘要波动；本项目是批量抽取，单次运行，仍无多 seed。
